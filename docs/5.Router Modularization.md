# Router modularization

Folder Tree
```zsh
backend/
├─ package.json
├─ src/
│  ├─ server.js
│  ├─ controllers/
│  │  └─ notesController.js → Handles business logic for note actions
│  └─ routes/
│     └─ notesRoutes.js → Handles /api/notes endpoints
```

## seprate modular
### /backend/server.js
```js
import notesRoutes from "./routes/notesRoutes.js";

app.use("/api/notes", notesRoutes)
```
app.use:
- app → your Express application object.
- use() → is used to register middleware or routes.

It means: when the request path matches, pass the request to the specified route handler (notesRoutes).

### backend/routes/notesRoutes.js
```js
import express from "express";

const router = express.Router(); // const app = express();

router.get("/", (req, res) => {
    res.status(200).send("You just fetched the notes");
});

router.post("/", (req, res) => {
    res.status(201).json({message: "Note created successfully"});
});

router.put("/:id", (req, res) => {
    res.status(200).json({message: "Note updated successfully"});
});

router.delete("/:id", (req, res) => {
    res.status(200).json({message: "Note deleted successfully"});
});

export default router; // make `routers` available outside the file
```
`const router = express.Router();`
- Create a new Router object from Express
- Think of this as a "mini Express app" that can handle its own routes and middleware.
- We use it to organize related routes in a separate file instead of cluttering app.js.
const router = express.Router();

`export default router;`
- make `routers` available outside the file

## Add controllers.file
```js
export async function getAllNotes(req, res) {
    res.status(200).send("You just fetched the notes");
};

export function createNotes(req, res) {
    res.status(201).json({ message: "Note created successfully" });
};

export function updateNotes(req, res) {
    res.status(200).json({ message: "Note updated successfully" });
}

export function deleteNotes(req, res) {
    res.status(200).json({ message: "Note deleted successfully" });
}
```
- `async`: 
    - async marks a function as **asynchronous**. Automatically return 'Promise'
    - Asynchronous = code can start a task and continue immediately, not waiting
- `await`: can only be used inside an async function.
    - await = “Pause inside this function until the Promise changes from pending → fulfilled, then continue with the result.”

In controller file, usually write funtions and then export them so that your routes file can import and use them.

Import into backend/routes/notesRoutes.js
```js
import { getAllNotes } from "../controllers/notesControllers.js";

router.get("/", getAllNotes);
router.post("/", createNotes);
router.put("/:id", updateNotes);
router.delete("/:id", deleteNotes);

export default router;
```
`../` means go up one folder

Import into backend/server.js
```js
import express from "express";
import notesRoutes from "./routes/notesRoutes.js";

const app = express();

app.use("/api/notes", notesRoutes)

app.listen(5001, () => {
    console.log("Server started on PORT:5001")
});
```
Q: Why use controllers + routes?
A: Organization, Scalability and Reusability. MVC pattern(Model-View-Controller). Routes→only define the endpoints. Controllers→contain the actual functions that handle requests.
